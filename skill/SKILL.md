# 只測不修的 QA

這是純黑箱測試：只透過受測對象的畫面與行為來判斷，不讀取原始碼，也不需要有原始碼。報告描述的是「看到什麼現象、怎麼重現」，不推測程式哪裡寫錯。

流程本身與平台無關：寫計畫、逐流程操作、留證據、產報告。實際「操作畫面」交給驅動程式，換平台只換驅動程式，這份流程不變。

## 第 0 步：確認輸入（最少互動）

必要輸入有三項，使用者已在指令中給的就不再問；缺的用 AskUserQuestion 一次問完，無法使用時改以文字詢問。

1. **受測對象**：網站給網址，單一的靜態網頁可以直接給 `.html` 檔案的路徑，App 給平台與啟動方式，其他類型說明怎麼進入。僅接受本機或開發環境；看起來是 SIT／UAT／PROD 時先停下來向使用者確認，未確認不操作。
2. **測試範圍**，依下列順序取得：
   - 使用者指定的畫面或流程。
   - 使用者提供的測試案例或規格文件。
   - 以上皆無時，先把受測對象的主要畫面走一遍，整理出可測的流程清單，列給使用者確認後再測。
3. **測試帳號**：由使用者當下提供，只在本次操作使用，不寫入任何檔案與報告。登入方式依驅動程式的說明檔，預設由使用者自己在跳出的視窗裡登入，密碼不經過對話；使用者也可以選擇直接在對話中給測試密碼。只接受測試帳號，使用者給的若像是真實帳號或正式環境的密碼，先停下來確認。

報告目錄：放在目前工作資料夾（使用者啟動 Claude Code 的那個資料夾）底下的 `reports\<yyyyMMdd-HHmmss>-<受測對象名稱>\`，日期時間放前面，資料夾才會照時間排序。例如 `reports\20261117-103321-demo-page\`。每次執行開新的資料夾，不覆寫舊報告。測試計畫、截圖、報告都存在這裡。使用者另外指定位置時依使用者的。

## 安全限制（一律適用）

- [只測不修] 只允許在報告目錄內建立檔案，以及把報告發佈成 Artifact。發現問題只記錄，不動手修，也不呼叫其他會修改程式的 skill。
- [黑箱] 不讀取、不搜尋、不修改任何原始碼，不執行 git、建置或專案的測試指令。即使目前的工作目錄剛好是受測對象的專案也一樣。
- [環境] 不對 SIT／UAT／PROD 操作，不主動連線任何資料庫。
- [測試資料] 只用測試帳號與測試資料。畫面上出現疑似真實客戶資料時立即停止該流程、不截圖，並回報使用者。截圖無法事後隱碼，所以要從來源避免。
- [機敏資訊] 報告文字不得出現真實帳號、密碼、Token、身分證號、卡號、內部 IP、內部 hostname；一律用 placeholder（例如 `<TEST_ACCOUNT>`、`A123456789`）。
- [破壞性操作] 刪除、送出交易、寄送通知這類不可逆的動作，測到送出前一步為止，除非使用者明確說可以送出。

## 選擇驅動程式

依受測對象的平台，讀 `drivers\` 下對應的說明檔再開始操作。

| 平台 | 驅動程式 | 說明檔 |
|---|---|---|
| 網站、可在瀏覽器開啟的前端（含 Cordova 的網頁層） | 內建 | `drivers\web.md` |
| 其他平台 | 尚未提供 | `drivers\README.md` 說明驅動程式要提供什麼、怎麼新增 |

每個驅動程式都提供同一組動作，下面的測試流程只用這組動作來描述：

| 動作 | 用途 |
|---|---|
| 開始／結束 | 啟動受測對象的操作環境，測完關閉並清掉暫存資料 |
| 開啟 | 進入指定的畫面或入口 |
| 列出元素 | 看目前畫面上有哪些可操作的元件 |
| 點擊 | 按鈕、連結、選項 |
| 輸入 | 文字欄位、選單 |
| 讀取畫面內容 | 確認文字、欄位值、錯誤訊息 |
| 截圖 | 每個檢查點留證據 |
| 讀取執行紀錄 | 錯誤、警告、未處理的例外 |
| 讀取網路紀錄 | 失敗或回應異常的請求 |

受測平台沒有對應的驅動程式，或驅動程式無法啟動時：不要假裝測過，也不要改用未經使用者同意的工具。直接告訴使用者目前測不了與原因，不產出看似完整的報告。驅動程式只是缺少某個動作時（例如該平台讀不到網路紀錄），照常測試，並把缺的部分寫進報告的未測範圍。

## 測試流程

### 1. 先寫測試計畫，再開始操作

每條流程在動手前寫下四件事，存成報告目錄下的 `plan.md`：

- 入口：從哪個畫面、什麼狀態開始。
- 預期結果：依使用者提供的規格或現有行為，成功時應該看到什麼。
- 風險點：這條流程最容易出錯的地方。
- 結束條件：測到哪裡算這條流程走完。

沒有規格可依據的預期結果，標「依現有行為推斷」，不當成規格。

### 2. 逐條流程操作

每條流程依序走這四類情境，不適用的在報告註明略過原因：

1. 正常路徑：用合理的資料走到結束條件。
2. 輸入檢核：必填留空、只填空白、格式錯誤、超過長度、特殊字元。
3. 邊界值：最小值、最大值、零、空清單、金額與日期的臨界。
4. 中斷與回復：返回、重新載入、重複點擊送出、逾時後再操作。

每個檢查點做三件事：截圖、看執行紀錄、看網路紀錄。截圖存到 `screenshots\`，檔名用「流程序號-步驟序號-簡述」。

### 3. 發現異常時

- 先從頭重現一次。重現得出來才列為問題；重現不出來的列在「偶發現象」，附當時的截圖與操作步驟。
- 記下最短的重現步驟，去掉與問題無關的操作。
- 只描述觀察得到的事實：畫面顯示什麼、執行紀錄與網路紀錄出現什麼。不推測程式原因，也不去找原始碼。

### 4. 產出報告

報告的章節與欄位依 `templates\report-template.md`。交付方式有兩種，先試第一種：

1. **發佈成 Artifact**（預設）：有 Artifact 工具可用時，把報告做成一頁 HTML，讓使用者直接在頁面上看到每個問題和對應的截圖。寫頁面前先載入 `artifact-design` skill。做法：
   - 截圖轉成 base64 直接嵌在頁面裡，不要當附屬檔案發佈，這樣報告是單一檔案，離線也看得到圖。
   - 發佈用的檔案放在暫存目錄；報告目錄另存一份 `qa-report.html`，開頭補上 doctype 與 `<meta charset="utf-8">`，讓使用者不連網也能直接用瀏覽器打開。
   - 頁面最上面用一句話回答使用者問的問題，接著才是明細。
2. **只存本機**（退路）：沒有 Artifact 工具、發佈失敗、或使用者不想發佈時，只在報告目錄留下 `qa-report.html`（做法同上，截圖內嵌）。

發佈前的確認：
- Artifact 會把報告與截圖上傳到 claude.ai，預設只有使用者自己看得到。受測對象是公開網站時直接發佈。
- 受測對象是公司內部或需要登入才看得到的環境時，發佈前先問使用者一次要不要上傳；不要的話走第二種。
- 不論哪一種，都不替使用者把報告分享給其他人。

原則：
- 只列實際測到的問題，沒有就明說沒有，不湊數。
- 同一種問題出現在多處時合併成一項，列出所有位置。
- 「未測範圍」必填。沒測到的畫面、情境、被擋住的原因都要寫，讓讀報告的人知道綠燈的範圍到哪裡。
- 不替問題分嚴重度或決定修不修，那由讀報告的人判斷。問題依流程與步驟的順序列出。
- 每個問題附一條建議的回歸測試案例（Given-When-Then，中文描述），只寫案例，不寫測試程式。

## 回報

測完後在對話中回覆：報告的連結（有發佈成 Artifact 時）與報告目錄的完整路徑、問題數量、未測範圍一句話摘要。沒有發佈時說明原因。不重貼整份報告。

## 補充規則

- 測試途中需要的東西不存在（測試資料、權限、後端沒啟動）時，把相關流程標為「受阻」並繼續測其他流程，不自行建立資料或啟動服務，除非使用者同意。
- 同一範圍重測時，前一輪使用者已裁決「不處理」的項目不重列，只在報告末尾帶一行。
