# 只測不修的網站 QA

## 第 0 步：確認輸入（最少互動）

必要輸入有三項，使用者已在指令中給的就不再問；缺的用 AskUserQuestion 一次問完，無法使用時改以文字詢問。

1. **測試網址**：僅接受本機或開發環境。網址看起來是 SIT／UAT／PROD 時先停下來向使用者確認，未確認不操作。
2. **測試範圍**，依下列順序取得：
   - 使用者指定的頁面或流程。
   - 對話中已有的測試案例或規格。
   - 以上皆無時，用唯讀 git 看未 commit 變更，推斷受影響的頁面，列給使用者確認後再測。
3. **測試帳號**：由使用者當下提供，只在本次操作使用，不寫入任何檔案與報告。密碼走環境變數，不貼在對話裡（見「瀏覽器操作」的使用規則）。

選填：報告目錄。未提供時用 `%USERPROFILE%\qa-reports\<專案名>\<yyyyMMdd-HHmmss>\`，一律放在 repo 之外，避免截圖被掃進 commit。每次執行開新的時間戳目錄，不覆寫舊報告。

## 安全限制（一律適用）

- [只測不修] 只允許在報告目錄內建立檔案。不修改產品程式、測試、設定、依賴；發現問題只記錄，不動手修，也不呼叫其他會修改程式的 skill。
- [Git] 僅允許唯讀操作：status、log、diff、show、branch（列表）。
- [環境] 不對 SIT／UAT／PROD 操作，不主動連線任何資料庫。
- [測試資料] 只用測試帳號與測試資料。畫面上出現疑似真實客戶資料時立即停止該流程、不截圖，並回報使用者。截圖無法事後隱碼，所以要從來源避免。
- [機敏資訊] 報告文字不得出現真實帳號、密碼、Token、身分證號、卡號、內部 IP、內部 hostname；一律用 placeholder（例如 `<TEST_ACCOUNT>`、`A123456789`）。
- [破壞性操作] 刪除、送出交易、寄送通知這類不可逆的動作，測到送出前一步為止，除非使用者明確說可以送出。

## 瀏覽器操作

用本 skill 自帶的驅動程式 `scripts\browser-driver.mjs`（與本檔同目錄）。它只用 Node 內建模組，操作本機已安裝的 Edge，走行程間管道不開 port，每次用一次性的空白 profile，結束時整個刪除。需要 Node 22 以上。

下表的 `driver` 代表 `node "<本 skill 目錄>\scripts\browser-driver.mjs"`。每個指令回傳一段 JSON，`ok` 為 false 時讀 `error`。

| 動作 | 指令 | 用途 |
|---|---|---|
| 開始 | `driver start --out "<報告目錄>\screenshots"` | 啟動瀏覽器。每次測試只開一個 |
| 開啟網址 | `driver open <url>`、`driver back`、`driver reload` | 進入頁面、上一頁、重新整理 |
| 看有哪些元素 | `driver elements` | 列出可操作的欄位、按鈕、連結與建議的 selector |
| 點擊 | `driver click <selector>` | 按鈕、連結、勾選框 |
| 輸入 | `driver fill <selector> <值>` | 文字欄位與下拉選單；值給空字串代表清空 |
| 按鍵 | `driver press <Enter\|Tab\|Escape>` | 送出表單、切換焦點 |
| 等待 | `driver wait <selector\|毫秒>` | 等元素出現 |
| 讀取頁面內容 | `driver text` | 確認文字、錯誤訊息 |
| 截圖 | `driver shot <檔名> [--full]` | 存成 PNG，回傳完整路徑；用 Read 看圖 |
| 讀取 console | `driver console` | 上次讀取之後的 error、warning、未捕捉例外 |
| 讀取 network | `driver network` | 上次讀取之後狀態碼 400 以上或失敗的 request，以及被擋的導覽與對話框紀錄 |
| 結束 | `driver stop` | 關瀏覽器並刪除 profile |

使用規則：

- selector 用 CSS selector，或 `text=登入` 這種依可見文字比對的寫法。不確定時先跑 `elements`。
- 密碼欄位只接受環境變數：`driver fill "#pwd" env:QA_PWD`，直接給值會被驅動程式拒絕，步驟檔也一樣。環境變數必須在啟動 Claude Code 之前就存在（使用者層級的環境變數，設完要重開 Claude Code），對話中途才設的讀不到。開始前用 `driver hasenv QA_PWD` 確認，它只回有或沒有，不會印出值。沒有的話請使用者設好再重開，不要請使用者把密碼貼進對話。
- 預設只能瀏覽本機。開發環境主機要在開始時加 `--allow <主機名>`（多個用逗號分隔），加之前先跟使用者確認該主機是開發環境。不在白名單的導覽會被擋下，並出現在 `network` 的 `notes`；頁面會停在錯誤頁，用 `back` 回去。白名單只管頁面與 iframe 的導覽，已允許的頁面自己發出的 API 請求不受限。
- 行動版頁面在開始時加 `--viewport 390x844`。想看著它操作時加 `--headed`。
- 原生對話框會自動處理並記在 `network` 的 `notes`：alert 按確定，confirm 與 prompt 按取消。要測「按確定」的分支時，在報告的未測範圍註明。
- 新開分頁會被自動關閉並留下紀錄，目前不支援跨分頁流程。
- 連續多步且中間不需要判斷時，把步驟寫成 JSON 陣列存到報告目錄，用 `driver run <檔案>` 一次跑完，遇到第一個失敗就停。
- **測完一定要 `driver stop`**，中途放棄也要。忘了的話它閒置 15 分鐘會自己結束。

驅動程式無法啟動時（沒有 Node、沒有 Edge、被端點防護擋下）：不要假裝測過，也不要改用其他未經使用者同意的工具。改做不需要畫面的檢查（讀程式比對規格、執行專案既有的自動化測試），並在報告的「未測範圍」明寫畫面操作全數未測與原因。

## 測試流程

### 1. 先寫測試計畫，再開始操作

每條流程在動手前寫下四件事，存成報告目錄下的 `plan.md`：

- 入口：從哪個頁面、什麼狀態開始。
- 預期結果：依規格或現有行為，成功時應該看到什麼。
- 風險點：這次變更最可能弄壞的地方。
- 結束條件：測到哪裡算這條流程走完。

沒有規格可依據的預期結果，標「依現有行為推斷」，不當成規格。

### 2. 逐條流程操作

每條流程依序走這四類情境，不適用的在報告註明略過原因：

1. 正常路徑：用合理的資料走到結束條件。
2. 輸入檢核：必填留空、格式錯誤、超過長度、特殊字元。
3. 邊界值：最小值、最大值、零、金額與日期的臨界。
4. 中斷與回復：上一頁、重新整理、重複點擊送出、逾時後再操作。

每個檢查點做三件事：截圖、看 console、看 network。截圖存到 `screenshots\`，檔名用「流程序號-步驟序號-簡述」。

### 3. 發現異常時

- 先從頭重現一次。重現得出來才列為問題；重現不出來的列在「偶發現象」，附當時的截圖與操作步驟。
- 記下最短的重現步驟，去掉與問題無關的操作。
- 可唯讀查看原始碼來指出可能位置，但只寫「可能位置」，不下定論、不改。

### 4. 產出報告

依 `templates\report-template.md` 寫成報告目錄下的 `qa-report.md`。

分級：
- **必修**：功能無法完成、資料錯誤、資安問題、畫面壞到無法操作。
- **建議修**：功能可完成，但行為與規格不符或明顯不合理。
- **可不修**：文案、排版這類不影響操作的細節。

原則：
- 只列實際測到的問題，沒有就明說沒有，不湊數。
- 同一種問題出現在多處時合併成一項，列出所有位置。
- 「未測範圍」必填。沒測到的頁面、情境、被擋住的原因都要寫，讓讀報告的人知道綠燈的範圍到哪裡。
- 每個必修與建議修的問題附一條建議的回歸測試案例（Given-When-Then，中文描述），只寫案例，不寫測試程式。

## 回報

測完後在對話中回覆：報告的完整路徑、各級問題數量、未測範圍一句話摘要。不重貼整份報告。

## 補充規則

- 當前工作區 CLAUDE.md 比上述更嚴時，從嚴適用。
- 測試途中需要的東西不存在（測試資料、權限、後端沒啟動）時，把相關流程標為「受阻」並繼續測其他流程，不自行建立資料或啟動服務，除非使用者同意。
- 同一範圍重測時，前一輪使用者已裁決「不處理」的項目不重列，只在報告末尾帶一行。
