# 驅動程式

qa-report 的測試流程與平台無關，「操作畫面」這一層由驅動程式負責。新增一個平台只需要新增一個驅動程式，`SKILL.md` 的流程與報告範本都不用改。

## 目前的狀態

| 平台 | 狀態 | 說明檔 |
|---|---|---|
| 網站、可在瀏覽器開啟的前端 | 內建 | `web.md` |
| Android App | 尚未提供 | — |
| iOS App | 尚未提供 | — |
| 桌面應用程式、API、命令列工具 | 尚未提供 | — |

## 驅動程式要提供的動作

| 動作 | 必要 | 回傳 |
|---|---|---|
| 開始 | 是 | 是否成功、截圖輸出位置 |
| 結束 | 是 | 是否已關閉並清掉暫存資料 |
| 開啟 | 是 | 目前所在的畫面 |
| 列出元素 | 是 | 可操作的元件清單，每個附一個可用來定位的識別方式 |
| 點擊 | 是 | 操作後所在的畫面 |
| 輸入 | 是 | 操作後所在的畫面 |
| 讀取畫面內容 | 是 | 畫面上的可見文字 |
| 截圖 | 是 | 圖檔的完整路徑 |
| 讀取執行紀錄 | 盡量 | 上次讀取之後的錯誤與警告 |
| 讀取網路紀錄 | 盡量 | 上次讀取之後失敗或異常的請求 |

標「盡量」的動作在某些平台做不到。做不到時要在說明檔寫明，測試時會列進報告的未測範圍。

沒有畫面的對象（API、命令列工具）不適用點擊與截圖，對應的做法是「送出請求或指令」與「保存回應內容」。

## 每個驅動程式都要守的規則

- **不擴大可接觸的範圍**：預設只能碰本機，其他對象要使用者明確允許。
- **不碰使用者既有的資料**：用一次性的環境，不讀取使用者平常使用的帳號、cookie、已安裝的 App 資料。
- **密碼不落地**：密碼只從環境變數讀，不出現在指令列、步驟檔、輸出。
- **輸出去識別**：回傳內容不帶 token、query 參數、密碼欄位的值。
- **不常駐**：測完能完整關閉，異常時也有辦法強制結束，並且有閒置自動結束。
- **依賴最少**：優先用平台本身已有的工具與 Node 內建模組。需要新 dependency 時先提出等確認。
- **失敗要明講**：每個動作回傳是否成功與原因，不回傳看似成功的空結果。

## 新增一個驅動程式

1. 在 `scripts\` 下新增程式，提供上表的動作，每個動作回傳一段 JSON。
2. 在本目錄新增 `<平台>.md`，比照 `web.md` 寫：適用範圍、指令對照表、使用規則、這個驅動程式測不到的。
3. 在 `SKILL.md` 的「選擇驅動程式」表格加一列。
4. 用一個已知有問題的受測對象實際跑一輪，確認每個動作都能用，再把結果補進說明檔。
5. 驅動程式會控制受測環境並處理登入，使用前需通過 Code Review 與資安複核。
