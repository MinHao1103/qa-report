## 問題清單

### 1. [建議修] 空購物車可以一路走到訂單確認頁

- **位置**：購物車頁、結帳流程
- **重現步驟**：
  1. 登入後不加任何商品，點右上角購物車。
  2. 點 Checkout。
  3. 收件資訊三欄各填一個字元，點 Continue。
- **預期**：購物車為空時不能結帳（依現有行為推斷）。
- **實際**：進入訂單確認頁，商品列表為空，金額為 $0，Finish 按鈕可按。重現兩次皆同。
- **證據**：`screenshots\2-3-empty-cart-checkout.png`、`screenshots\2-3a-repro-empty-cart-overview.png`
- **可能位置**：無原始碼，無法指出。
- **建議回歸測試**：
  - Given: 使用者已登入且購物車為空
  - When: 使用者在購物車頁點選結帳
  - Then: 無法進入結帳流程，並提示購物車沒有商品

### 2. [建議修] 收件資訊只填空白字元可通過必填檢核

- **位置**：結帳第一步（收件資訊）
- **重現步驟**：
  1. 購物車有商品時點 Checkout。
  2. First Name、Last Name、Postal Code 各輸入一個空白字元。
  3. 點 Continue。
- **預期**：只有空白應視為未填，顯示必填錯誤（依現有行為推斷，三欄留空時確實會擋）。
- **實際**：通過檢核，進入訂單確認頁。只把郵遞區號填空白、另外兩欄正常填寫時也一樣。
- **證據**：`screenshots\2-3-overview-space-postal.png`、`screenshots\2-3b-repro-space-only.png`
- **可能位置**：無原始碼，無法指出。推測必填檢核沒有先去除前後空白。
- **建議回歸測試**：
  - Given: 使用者在收件資訊頁，購物車有商品
  - When: 使用者在任一必填欄位只輸入空白並送出
  - Then: 顯示該欄位為必填的錯誤訊息，停留在收件資訊頁

### 3. [建議修] 內頁直接開啟或重新整理時，伺服器回應 HTTP 404

- **位置**：`/inventory.html`、`/checkout-step-one.html`、`/checkout-step-two.html`
- **重現步驟**：
  1. 登入。
  2. 在任一內頁按重新整理，或直接以網址開啟該頁。
- **預期**：頁面正常顯示時，文件請求應回 200（依現有行為推斷）。
- **實際**：畫面正常顯示，但該頁的文件請求狀態碼是 404，console 出現對應錯誤。每次都發生。
- **證據**：network 紀錄：`GET /inventory.html` 404、`GET /checkout-step-one.html` 404、`GET /checkout-step-two.html` 404
- **可能位置**：無原始碼，無法指出。推測是單頁應用以 404 頁面當作路由入口。
- **建議回歸測試**：
  - Given: 使用者已登入
  - When: 使用者直接以網址開啟商品列表頁
  - Then: 頁面正常顯示，且文件請求的狀態碼為 200

### 可不修

- 登入頁：登入失敗時，頁面送往第三方錯誤回報服務的請求全部回 401，console 有對應錯誤。不影響操作。
- 結帳第一步：從訂單確認頁按上一頁回來，先前填的收件資訊被清空，需要重填。
